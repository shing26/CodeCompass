# Issue 03 — isTestPath 不认 `*.test.tsx` / `*_test.go`，测试符号进孤儿桶

> *This was generated by AI during triage.*

Status: bug / ready-for-agent

## 现象（复现仓库：CodeCompass 本仓库，repoId `repo-878b3614-80e9-4944-a222-3a2e6e75db58`）

scan 孤儿桶 top10 中 8 个是 `apps/repoqa-web/src/App.test.tsx` 的测试夹具方法（`makeClient` 的 `send`/`close`/`dispatch`、`constructor` 等）——它们通过 mock 对象动态调用，是典型假阳性；孤儿桶 total 1166/1406 ≈ 83%。

## 根因

`services/control-plane/src/diagnose-engine.ts:31-34`：

```ts
export function isTestPath(filePath: string): boolean {
  const p = filePath.replace(/\\/g, '/').toLowerCase();
  return p.includes('/test/') || p.includes('/src/test') || p.includes('test/java');
}
```

只认 Java 目录式路径；`*.test.ts` / `*.test.tsx` / `*.spec.ts` / `*_test.go` / `*.test.go` 全部漏掉。而 `domain-radar-engine.ts:66` 的注释声称 "drops test paths"——代码注释与实际覆盖面不符。

## 修复

- `isTestPath` 补文件名模式：`/\.(test|spec)\.[cm]?[jt]sx?$/`、`/_test\.go$/`。注意保留现有三个目录式规则不动（Java 存量依赖它）。
- `diagnose-engine.test.ts` 补边界 case（`App.test.tsx`、`foo_test.go`、非测试的 `latest.ts` 不误伤）。
- 修后本仓库 scan 孤儿桶 total 应显著下降（测试夹具移出候选）。

## 影响面

`isTestPath` 是导出函数，`domain-radar-engine.ts`、diagnose 等多处引用——修改是纯放宽（多排除测试路径），需检查是否有调用方依赖"test 目录文件仍算 production"的行为（预计没有，但 agent 应 grep 引用点确认）。

## 验收

- 单测覆盖新模式；546+ 单测与 e2e 全绿；本仓库重跑 scan 孤儿桶 top10 无 `*.test.*` 文件符号。
