## 根因（已定位到行）

两段代码叠加：

1. **`services/control-plane/src/languages/GoAdapter.ts:490-498`**——裸标识符调用（Go 包级函数调用，如 `Run(...)`）走 `first?.name === 'VariableName'` 分支，`dynamic: !scope?.selfType`。包级函数（`main`、`Start`）与顶层调用无 selfType → **恒为 dynamic:true**。
2. **`GoAdapter.ts:464-489`**——跨包选择器调用（`app.Start(...)`），`app` 是 import 包名，不在 `scope.params/locals/declaredTypes` 里 → `receiverType === undefined` → **dynamic:true**。
3. **`services/control-plane/src/repoqa-callchain.ts:602-620`**——resolver 对 `call.dynamic === true` 直接跳过名字解析，返回 `STATIC_ANALYSIS_BREAK_DYNAMIC`。

结果：Go 项目几乎全部跨函数调用边（同包裸调用 + 跨包 `pkg.Func`）对孤儿桶/hubs/trace/diagnose 不可见。JavaAdapter 对裸调用是 `dynamic:false`（`JavaAdapter.ts:450`），所以 Java 不受此影响——petclinic 的孤儿桶主因是 DI 反射而非边丢失，属另一个 issue（04）。

## 修复方向（建议，agent 可按代码实际情况调整）

- 最小修：GoAdapter 裸标识符调用标 `dynamic:false`。Go 无方法重载，`repoqa-callchain.ts` 的同名解析（sameFile → global）对 Go 是确定性的，走 Java 同款 fallback 即可。
- 增强修（推荐一并做）：跨包 `pkg.Func` 调用利用文件 import 声明映射——`app.Start` 的 `app` → `github.com/jesseduffield/lazygit/pkg/app`，可确定解析目标包；实现代价可控，收益是把 43% 假阳性压到仅剩接口/反射残余。
- 同一包内跨文件的同名冲突（Go 同包可跨文件）在名字解析时已由 sameFile 优先兜底，注意 `_test.go` 同名测试辅助的干扰。

## 影响面

scan（orphanedPublic in-degree、hubs PageRank）、`trace_call_chain`、`diagnose`、`refactor_plan` 共用 `buildFullCallersIndex`，修复全部受益。lazygit 修后 deepChains 也可能首次产出非空结果（目前 total=0 部分源于此）。
