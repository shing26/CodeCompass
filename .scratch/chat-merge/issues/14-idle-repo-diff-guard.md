## Agent Brief

**Category:** bug
**Summary:** 未索引完成（`status: 'idle'`/无 commit 历史）的仓库进「Diff 影响面」，base/head 下拉为空，但「运行差异分析」按钮不禁用；点击 → 后端 400 → 前端把原始 git 错误直排给用户。

**Current behavior:**
`ArchitectureDeltaView` 的 delta-run 按钮 `disabled={loading || !base.trim() || !head.trim()}`——看似有空值守卫，但 idle 库根本拿不到 ref，用户面对空下拉与一个语义不明的失败。错误经 `delta-error-detail` 呈现工程师级 git 术语（`fatal: ...`）。

**Desired behavior:**
- 仓库非 `ready` 或无可用 ref 时，delta-run 禁用并给 tooltip/inline 说明「该仓库尚未索引完成或无可用 Git 引用，请先在「更多操作」重建索引」
- 真失败时错误首行改为人话（「该仓库不是有效的 Git 仓库，或指定的 ref 不存在」），原始 git 输出折叠到可展开区
- 服务端 400 响应体（`/api/repos/:id/diff`）的错误文案首行同样收敛，原始 stderr 置于次要字段

**Key interfaces:**
- `ArchitectureDeltaView` 的 delta-run `disabled` 条件 — 增加 `repo.status !== 'ready' || (!baseOptions.length && !headOptions.length)`
- diff 端点的错误响应形状 — 增加 `detail`（原始输出，前端折叠），`error`（人话首行）；契约变更 additive、不改字段语义
- 前端错误渲染 — `error` 常显、`detail` 用 `<details>` 折叠

**Acceptance criteria:**
- [x] idle 库（如 fixture repo）进 Diff：delta-run disabled，或有明确「先重建索引」引导；点击不可触发 400
- [x] ready 库填错 ref：错误首行不含 `fatal`/`usage:` 等 git 术语，原始输出在可展开区
- [x] 控制面 diff 端点测试绿；新增断言覆盖 detail/error 两字段
- [x] web 全量绿；e2e 现有 diff 断言不回归

**Out of scope:**
- 引入 ref 自动补全/图可视化；「先选仓库」占位提示的**样式**重设计（文案收敛在本票）
