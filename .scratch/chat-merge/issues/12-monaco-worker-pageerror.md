# 12：Monaco editor.worker 每次开检查器抛 3 条未捕获 pageerror（QA-03）

## Agent Brief

**Category:** bug
**Summary:** 打开代码检查器（挂载 monaco 编辑器）时，控制台固定出现 3 条未捕获 `TypeError: Cannot read properties of undefined (reading 'toUrl')`，栈在打包出的 `editor.worker` chunk 内（`toUri → asBrowserUri`）。页面表面不崩（代码视图正常），属静默失败 + 控制台污染。

**裁决（maintainer 2026-09-10）：走 worker 工厂化，不升级 monaco 版本。**

**Current behavior:**
monaco 的 worker 环境用 `?worker` 打包方式接入；editor worker 在解析 URI 时命中 undefined，抛未捕获错误。每次 Inspector 挂载复发。

**Desired behavior:**
改用 `MonacoEnvironment.getWorker(_, label)` 按 label 提供 worker 工厂（至少正确提供 `editor` label 的 worker），消除未捕获 pageerror。**monaco-editor 依赖版本保持不变**（不升 0.53/0.52.x patch，避免版本风险）。

**Key interfaces:**
- monaco 初始化/配置模块（`monacoSetup` 型）— 设置 `self.MonacoEnvironment = { getWorker(_, label) { ... } }`
- Vite worker 导入形状 — `?worker` 默认导出可直接 `new Worker()`；工厂按 label 分发（editor 与可选 json/ts/css，本项目只需 editor）

**Acceptance criteria:**
- [x] 连续开关检查器 ×3，浏览器 `pageerror` 计数 = 0（Playwright 监听 `page.on('pageerror')`）
- [x] 代码视图仍正常渲染、语法高亮工作（worker 真在跑，不是被 swallow）
- [x] `package.json` monaco 版本零变化
- [x] web 全量测试绿；生产构建后（非仅 dev server）同样无 pageerror

**Out of scope:**
- 升级 monaco 或改编辑器主题/交互；worker 之外的控制台错误归各自票

## Comments

- 根因（Playwright 生产包复现 + monaco 0.52.2 源码走读，非猜测）：`self.MonacoEnvironment.getWorker()` 对**所有 label** 返回 editor worker。但 `import * as monaco from 'monaco-editor'` 会 eager 注册 TS/JSON/CSS/HTML 语言贡献——Inspector 打开 `.ts` 文件后，TS 语言服务用 `createWebWorker({label:'typescript', moduleId:'vs/language/typescript/tsWorker'})` 要 worker，拿到的却是 editor worker；后者收到 `$loadForeignModule` 时无静态 foreign-module 工厂，落入 `editorSimpleWorker.js` 的动态 import 分支 → `FileAccess.asBrowserUri` → `toUri(e, n)` 的 `n` 未传（ESM 构建里恒 `undefined`）→ `n.toUrl` TypeError。崩溃在 worker 内，promise 静默 reject 成未捕获页错（每挂载 3 条 ≈ TS 语义 token 等三个代理）；后果不止噪音：TS 语义着色/diagnostics 从未工作过。
- 修复（按裁决=不升版本）：`monacoSetup.ts` 改按 label 工厂——json/css+scss+less/html+handlebars+razor/typescript+javascript 各回自己的官方 worker，default（含 'editor' 与 java 等无 worker 语言）回 editor worker。各 worker 为独立懒加载 chunk，主 bundle 不背 ts.worker 体积；monaco-editor 仍 0.52.2（package.json 零改动）。
- 验证：复现台 `.scratch/chat-merge/qa/t12-monaco-worker/repro.mjs`（playwright-core + 本机 ms-playwright chromium-1243；导入 CodeCompass 自身为 ready fixture，服务端托管 `dist` 生产包）：修复前 pageerror=13（栈 `…/editor.worker-*.js → toUri → asBrowserUri ← $loadForeignModule`，与 QA-03 报告逐字吻合）；修复后同一脚本 **pageerror=0 / console error=0**，3 个文件挂载 + 375px 抽屉 ✕/遮罩开关各 3 轮，token 跨度 112/154/236（高亮活），`page.on('worker')` 实证 `ts.worker-*.js` 与 `editor.worker-*.js` 真被实例化。web 全量 281/281 绿。
- 附带发现：修复前高亮其实正常（QA 所见视图无恙），但 jsdom 里 `.mtk` 探针不可靠；浏览器侧判据用 `[class*="mtk"]`。
