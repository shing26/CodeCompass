## Agent Brief

**Category:** bug
**Summary:** 浏览器后退使 URL 回到无 `?repo=` 的入口时，页面仍保持已选仓库与 tab 高亮——URL 与 UI 失同步，此时复制 URL/F5 会丢失上下文。

**裁决（maintainer 2026-09-10）：URL 是仓库选择的唯一真理源。** 后退到无 repo 参数的历史条目 = 取消选库（而非把状态反向写回 URL）。

**Current behavior:**
popstate 处理器只在「URL 携带 repo 且与当前不同」时行动；URL 不含 repo 参数时 no-op，UI 保留选库与 tab 高亮。QA 复现：`/` → 选库（push `?repo=R`）→ 切 Diff 影响面 → goBack → `location.search=""` 但选库/高亮仍在。

**Desired behavior:**
历史导航落到无 `repo` 参数的 URL 时，应用回到「未选库」状态：仓库目录清除当前选择、视图回到拓扑空态/引导、主区不再渲染任何库数据。**并显式清空检查器（文件内容/符号名）与关闭移动抽屉**——避免后退后残留上一库的源码切片（隐私与一致性双重理由）。前进（goForward）回到带 `?repo=` 的条目时能重新加载对应库。

**Key interfaces:**
- Repo 域 context 的 popstate 效果 — 补「URL 无 repo」分支：清除选择
- 检查器域 context — 需要一个可被调用的 reset（清 file/text/symbolName，历史栈一并清空或保留待定：实现时选择最小一致方案并在 PR 说明）
- 现「删除仓库」动线已有清除选库逻辑（selectRepo('')），复用同一状态机避免双标

**Acceptance criteria:**
- [x] QA 四步序列（`/` → 选库 → 切 tab → goBack）后：URL 无参数、TopBar 未选库、主区为引导/空态、检查器面板无残留文件内容、移动抽屉关闭
- [x] goForward 回到 `?repo=R&mode=diff`：选库与 tab 正确恢复
- [x] F5 / 复制后退后的 URL：落点状态与当前页面一致
- [x] 「删除仓库」「切换仓库」既有行为不回归；web 全量绿（含新回归用例）

**Out of scope:**
- 无 repo 深链 `?mode=diff` 的 tab 高亮错位（归 #16）；history 栈语义 pushState/replaceState 既有分工不动

## Comments

- 实现（2026-09-10，与 #16 同批）：`RepoContext.onPopState` 补「URL 无 repo」分支——复用删除动线的同一状态机 `selectRepo('')`，`setActiveTour(null)` + `setView(viewFromMode(...))`。「清检查器」走既有 `useInspector` 的 `[repoId]` 清空效果（file/text/symbolName/导航栈整体重置，与切库/删库行为一致，即票内「最小一致方案」的裁定：历史栈一并清）；`InspectorContext` 新增 `!repoId → setInspectorOpen(false)` 抽屉显式关闭。mode→视图解析收敛为 `viewFromMode` 单一映射（冷加载/popstate/选库三处共用）。
