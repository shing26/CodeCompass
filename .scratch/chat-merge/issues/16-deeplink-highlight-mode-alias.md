## Agent Brief

**Category:** enhancement
**Summary:** 两处分链行为让用户困惑：①无 repo 的 `?mode=diff` 深链——tab 高亮「Diff 影响面」但主区渲染拓扑引导（高亮与内容错位）；②`?mode=chat` 被接受后又被 replaceState 静默改写成 `?mode=incident`（用户分享/收藏的 URL 被悄悄换名）。

**裁决（maintainer 2026-09-10，按推荐）：** 高亮回退 + 别名文档化。归一化行为**保留**（incident 为唯一 mode 值，chat 为兼容别名），但须在文档与代码注释中显式声明双别名关系。

**Desired behavior:**
- 无当前仓库时，任何 `?mode=` 深链的 tab 高亮回退到「代码拓扑」（与渲染内容一致）；用户选库后 mode 参数自然再生效（现有 popstate/deepLink 机制已如此，只差高亮同步）
- `mode=chat` 与 `mode=incident` 的别名关系写入 HANDOFF/深链文档一行；URL 归一化到 incident 属既定行为（不再视为 bug）

**Key interfaces:**
- TopBar `activeView` 计算处 — 加入 repo 为空的回退条件（与主区渲染同一条件源，避免双判断漂移）
- 深链 mode 解析（URL → 视图映射，含冷加载与 popstate 两路径） — 只读确认别名映射集中一处

**Acceptance criteria:**
- [x] 无库访问 `/?mode=diff`：tab 高亮「代码拓扑」，主区引导，URL 保留 mode 参数不报错
- [x] 无库 → 选库后 mode 生效进入 Diff（既有行为不回归）
- [x] `?mode=chat` 冷加载进「架构问答」，URL 归一为 incident，且此别名在 HANDOFF 有记载
- [x] web 全量绿 + 新增高亮回退用例

**Out of scope:**
- 「先选仓库」引导占位的视觉重设计（#14 只管 idle/diff 反馈）；mode 参数体系扩展新值

## Comments

- 实现（2026-09-10，与 #13 同批）：高亮回退——`App.tsx` 定义共享条件 `const noRepo = repoId === null`，TopBar `activeView` 与主区渲染分支同源于此（无库时高亮恒为 topo，与引导内容一致；mode 参数在 URL 保留，view-sync effect 仅在视图切换时改写）。别名映射集中到 `RepoContext.viewFromMode` 单函数（incident 规范值、chat 兼容别名、归一逻辑注释显式声明），冷加载/popstate/选库三路共用。
- 实现补记：票面称选库后 mode 生效「机制已如此」，代码核实为误——旧 `handleSelectRepo` 恒 `setView('topo')` 且会把 mode 参数冲掉。已改为选库时经 `viewFromMode(URL.mode)` 落地，使验收 2 真实成立；副作用是 A 库停在 diff 时切 B 库会保持 diff 视图（URL 真理源方向上自洽）。
- 文档：别名与「后退无 repo = 取消选库」写入 README 深链条目（该文档实际承载深链说明；HANDOFF 无深链节）。
- 测试：`App.test.tsx` 用例 2（高亮回退 + 选库后 mode 生效）与用例 3（chat 别名冷加载 + URL 归一）。另给 Issue 31 describe 补 URL 卫生 beforeEach（残留 mode 与选库尊重 mode 新语义叠加会饿死同值 selectOptions，先例见 Issue 14 describe）。web 全量 279/279 绿。
