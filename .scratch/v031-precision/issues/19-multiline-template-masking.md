# Issue 19 — 多行模板串未被掩码 → 幻影声明（自指掩码缺陷）

> 依据：票 18(f)2 实现期实测（2026-09-24），探针 `.scratch/probe-mask.ts` / `.scratch/probe-ambiguity.ts`
> 判据：HANDOFF §2.2「降低误报」——幻影声明是**假符号**，会污染 `index.types` 与一切按名查表的解析路径
> 波次：待排 ｜ 状态：**已立项，待开工**（票 18 交付时**刻意未修**，见 §3）｜ 依赖：无

## 1. 缺陷（实测）

`TypeScriptAdapter.ts::maskLiteralsAndComments` 的 `'`/`"` 分支是**按行**的：

```js
/(["'`])(?:\\.|(?!\1)[^\\\n])*\1|\/\/[^\n]*|\/\*[\s\S]*?\*\//g
```

`[^\\\n]` 排除了换行，所以**多行模板串只被掩到第一个换行**，其后的内容按**源码**被扫描。后果是
`extractTypeOnlyDeclarations`（正则找 `interface X {`）会把**模板串里的文字**当成真声明，产出**幻影符号**。

实测证据（本仓，2026-09-24）：

```
# 票 18 新加的单测 fixture（多行模板串）声明了 interface RepoContextValue { client: RepoQAClient }
# → 与真声明 apps/repoqa-web/src/context/RepoContext.tsx 的内容不同
# → 跨文件表的歧义规则（正确地）把真表项丢弃 → pickFolder 绑定失败 → 复测"看起来没用"
```

幻影不止出现在测试里：**生产代码同样暴露**——`chat/agent.ts` 的系统提示词、`engine/repoqa-export.ts` 的导出模板
都是多行模板串，任何一段含 `interface Foo {` / `function bar(...)` 的文字都会变成符号或声明表条目。

## 2. 影响面（两个方向都要看）

| 方向 | 后果 | 严重度 |
|---|---|---|
| 幻影**接口/类型**符号 | `index.types` 多出真实不存在的类型；按名查表可能命中幻影 → **假边**（若幻影名恰与真类同名） | 中 |
| 幻影**声明表**条目（票 18 的表） | 与真声明同名异内容 → 歧义规则丢弃真项 → 该仓跨文件定型**整体失效**（fail-closed，不会造假边） | 中 |
| 符号计数/普查 | `type-declaration` 排除计数虚高，M2/桶统计被污染 | 低 |

**注意方向**：第二行是"沉默失效"——没有报错，只是精度变差，且**越是在测试/提示词写得多的仓库越容易触发**（本仓即中）。

## 3. 为什么票 18 交付时没顺手修（重要，别重复踩）

一行加宽 backtick 分支即可修（`` `(?:\\.|[^\\`])*` `` 允许跨行），但实测**会坏得更厉害**：

> 掩码器自身的源码与注释里就有反引号。跨行匹配后，**注释里的反引号会与远处的反引号配对**，
> 使中间的真注释文字**不被掩码**。本仓 `TypeScriptAdapter.ts` 当场自伤：其注释里的
> `` `interface RepoContextValue { … }` `` 变成幻影声明（探针 `probe-mask.ts` 输出 `masked@29859 line=760`）。

即：**掩码器必须先把注释/引号掩掉，才可能安全地按"模板串"匹配反引号**——这是顺序问题，不是正则强度问题。

## 4. 内容（正确修法：两阶段掩码）

1. **阶段一**：掩掉 `//…`、`/*…*/`、`'…'`、`"…"`（都按行，安全）。
2. **阶段二**：在阶段一的结果上再掩 `` `…` ``（允许跨行）。此时注释已消失，反引号配对不再被注释里的反引号带偏。
3. **正则字面量仍是残留风险**（`/`…`/` 里的反引号会参与配对）：至少让掩码器**自身源码不含字面反引号**
   （用 `\x60` 转义），并把"文件含反引号正则"记为已知边界写进注释。
4. 阶段划分必须**保持偏移不变**（同长空格替换），否则 `findClosingBrace` / 成员切片的偏移契约全崩。

## 6. 风险

1. **两阶段会改变全仓符号表**（幻影消失 → `symbolCount` 下降），棘轮比值会**被动上升**（分母变小）——
   必须在同一次变更里复算 ceiling 并写明理由，不能悄悄 `--ratchet-update`。
2. 反引号正则（如本仓掩码器自身）是已知边界，属"可解释下限"，不追求零。
3. 与票 18 同文件面（`TypeScriptAdapter.ts`），须串行。
