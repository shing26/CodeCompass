# Spec: v1.4 上手与可用性手术批（v1.4.0）

> **依据**：用户 2026-10-19 的三条产品批判 + 四步手术指令（原文：上手门槛高 / 画布毛线团 / 名为工具实为展示架；四步 = 30 秒获得感、聚焦模式、CLI 与 HTML 导出、人话与边界）。
> **立项**：2026-10-19 ｜ **前置**：v1.3.0（已发，tag 在档）｜ **版本预占**：**v1.4.0**（`git tag` 最新 = v1.3.0，CHANGELOG 顶部 = [1.3.0]，无并行线占号）。
> **性质**：本 spec 只规划；实现走 `issues/01–08`。

---

## 0. 一句话

三条批判**两条半已被历史交付覆盖**（画布从不存在全量铺开、CLI 已有 12 命令含单文件 HTML 导出）；本批只做核实后仍成立的真缺口：**让人零成本看到产品在干什么（示例 + 片段）、把「改代码才能用」的交互改成可点的、把 CLI 补到"敲一行就出结果"、把边界写成人话摆上台面。**

## 1. 现状核实（2026-10-19，先测再改）

| 批判 | 核实结论 | 判定 |
|---|---|---|
| ① 上手门槛高：要配环境、不知道填什么路径 | 导入仅本机路径（文案要绝对路径，服务端却隐式接受相对路径按 cwd 解析——契约与实现不一致）；**无示例项目**；**无片段粘贴** | 真缺口 → 票 01/02/03 |
| ① 括注：monorepo / `@/` 别名断链 | TS 适配器**不解析 import 声明**：跨文件按符号名消解，`@/` 别名不触发任何报错，同名符号靠「caller 自身文件 → 最早声明」确定性挑选（可错绑）；未解析边落入 BREAK/EXTERNAL/DYNAMIC 语义 | 真缺口但**大改风险高**（模块路径解析 = 引擎级重构，会动三仓精度棘轮）→ 诚实披露入票 06；**真实修复登记 deferred（票 08）** |
| ② 毛线团：G6 画布全量铺开/节点重叠/卡顿 | **不存在全量图渲染**：主画布只画 ≤3 张锚点卡；子图面板固定「上游 1 层 + 下游 1–3 层」；60 节点聚合截断。真正的失望点 = 深度不可调、无节点展开、聚合提示是**静态开发文案**「提高 maxNodes 可展开」（用户改不了代码） | 批判基本不成立；残留交互缺陷成立 → 票 04 |
| ③ 名义工具实为展示架 | **CLI 已存在**（根包 `@codecompass/cli`，12 子命令含 `context/diagnose/export`）；**单文件 HTML 导出已存在**（内联 mermaid、断网可渲染）。缺口 = 无 `trace` 命令（只有 `context`/`diagnose` 近似）、`--output` 参数名不匹配、Web 无导出入口 | 部分成立 → 票 05/07 |
| ④ 包装词与边界披露 | 无独立 Known Limitations 章节；边界散落；README 有口号式首句；CONTEXT.md 版本滞后（写 1.2.0，实为 1.3.0） | 真缺口 → 票 06 |

**已存在、本批不得重建**：CLI 12 命令、单文件 HTML 导出（内联 mermaid）、聚焦子图查询（Graph RAG 1+N 跳）、60 节点聚合与聚合提示、`code://` 深链、自动示例链路（首条 Top API）、仪表盘/导览/体检面、17 工具 MCP 面。

## 2. 范围裁决

### 2.1 冻结面（本批不动）
- **MCP 17 工具签名与数量冻结**（ADR-0016/0018/0020）：本批零新增工具、零签名变更。
- **引擎精度面零改动**：不碰 callchain/适配器逻辑（票 08 只是 deferred 登记）。
- 门禁只增不减：所有新行为须有测试；e2e 计数同步。

### 2.2 双轨制论证（ADR-0020，Web 面新增须答）
| 票 | dogfooding 论证 |
|---|---|
| 01 示例项目 | 维护者/评审者验证「导入→链路→导览」全管线的最短路径；每次验收不再依赖手边有大仓 clone；用户指令直提 |
| 02 片段粘贴 | 引擎开发期的即时验证面：一段代码解析对不对，不再为 20 行片段索引一个仓；用户指令直提（把使用成本降到零） |
| 04 子图焦点 | 日常读代码的主力交互（围绕一个方法看上下游）；现状固定深度 + 静态提示是「维护者自己也不会用」的交互 |
| 07 HTML 导出 | 分享单条链路给没装工具的人（评审/同事/面试场景）；把已有 CLI 能力接到用户手边 |

### 2.3 放弃清单（写下来才算裁决 —— 含触发线）
| 放弃项 | 理由 | 触发线 |
|---|---|---|
| 真实 tsconfig paths / import 模块路径解析 | 引擎级重构（需先解析 import 声明 + 建模块解析表），直接威胁三仓精度棘轮逐字节约束；不在「可用性手术」命题内 | 真实使用中出现别名导致的错绑/断链案例，且票 08 的披露不足以让用户正确判读 |
| G6 / 交互图库替换 mermaid | 全量图渲染在本产品不存在；替换渲染库不解决任何已核实问题，属「为界面而界面」 | 出现「需要同时看 >60 节点且聚合不足以表达」的真实任务 |
| 内嵌预解析 SQLite（免索引秒开） | 索引产物与引擎版本绑定，随包分发会成第二事实源；小样仓索引耗时可接受（实测入票 01） | 示例索引耗时 >10s 或真机验证不可接受 |
| Web 全量图新页签 | 双轨制「只为界面不加面」 | — |

## 4. 验收判据与纪律

1. **每票自带机器可验证判据**（票内 §验收），不接受"看起来对了"。
2. **新门须证明会红**（若新增门禁项）。
3. **Web 新增文案过双哨**：中文黑名单全文扫（含注释）+ 英文退役词区域扫；新组件测试随票。
4. **门禁基线（对照，2026-10-19 开工前实测）**：控制面 **809**、web **404**、bridge 26、e2e **73/0**；收口时同步实测新值入 HANDOFF §2.1。
5. **收口仪式**（照惯例）：版本五处推进（四本 package.json + version.ts）→ CHANGELOG `[1.4.0]` 段 → 双轴 code-review → 全量门禁 → HANDOFF 更新。npm 发布积压（0.31.0→1.4.0）仍在用户侧，收口时刷新 .cmd。
