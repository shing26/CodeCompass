# 票 04 — 子图焦点模式（深度可调 + 重定中心 + 聚合可展开）

Status: closed（已落地，2026-10-19，tag v1.4.0）

## 背景
用户批判②的残留真缺口（全量图渲染核实为不存在，见 spec §1）：子图面板固定「上游 1 层 + 下游 1–3 层」，无深度控件、无节点展开；60 节点聚合提示是静态文案「提高 maxNodes 可展开」——用户没有任何可操作入口。专业工具的 Call Hierarchy 心智 = 以当前方法为绝对中心、逐层展开。

## 目标
子图面板 = 焦点模式：默认上游 1 层 / 下游 1 层；深度可调（1–5）；点击节点把它变成新中心（可返回）；被聚合的节点有真按钮可展开。

## 实现要点
1. **HTTP**：`GET /api/repos/:id/subgraph-context` 新增 `callerDepth` / `calleeDepth` 查询参数（整数 0–5，clamp；缺省保持后端默认 1/3 不破坏既有调用方）。`routes/analysis-graph.ts` 透传到 `extractSubgraphContext` 既有选项。
2. **SubgraphPanel**：
   - 深度选择器：上游/下游两个 1–5 选择（默认 1/1，D3 裁决）；变更即重新请求
   - **点击节点 = 重定中心**：以该节点为新 start 重新请求子图；顶部面包屑显示当前中心 + 「返回」（回退栈，回到上一中心）
   - `code://` 深链保留在 **Ctrl/⌘+点击**（工具栏加一行说明文案），主点击不再跳文件
   - 展示 `prunedCount`/`truncated`（后端已算、现状未展示）：">N 个节点因预算未入图"
3. **MermaidDiagram 聚合提示改可操作**：`mermaid-notice` 从静态文案改为按钮「展开被聚合的 N 个节点」（点击后 maxNodes 提升到全量/240，取小者）；文案移除「提高 maxNodes 可展开」（保留给开发者的信息移入代码注释）
4. 不改：mermaid 渲染链路、trim 算法、方向过滤三态。

## 验收
1. 控制面测试：带 `callerDepth=2` 请求返回的节点距离分布 ≤2（构造夹具断言）；非法值 clamp。
2. Web 测试：深度选择器变更触发新请求参数；点击节点触发以该节点为中心的请求；「返回」回退；聚合按钮点击后渲染节点数增加。
3. 面板默认请求为 `callerDepth=1&calleeDepth=1`（测试断言）。
4. 真机走查：本仓 repo 里对某 service 方法操作三层展开 + 返回，无死路。
5. 「提高 maxNodes」静态文案全仓 grep 零命中（含测试）。

## Comments
**2026-10-19 落地。** 证据：
- HTTP：`callerDepth` / `calleeDepth`（0–5，越界钳制，非整数 400）；缺省仍 1/3，不破坏既有调用方。
- 面板：默认 1/1；深度选择 1–5；「中心：X」+ 返回轨迹（面板外换选中即清空）；`prunedCount` 上屏；点击节点=换中心、Ctrl/⌘+点击=纯源码跳转。
- **顺带修复**：子图节点深链此前静默失效——点击绑定按节点 id 索引、分发按渲染标签匹配，子图用哈希 id + `名字 · dN` 标签永不相等。新增 `parseLabelBindings` 兜底索引（`MermaidDiagram.tsx`）。
- 聚合提示改为可点「展开被聚合的 N 个节点」（上限 400）；静态语「提高 maxNodes 可展开」全仓零命中。
- 测试：CP 子图深度 1 项；`SubgraphPanel.test.tsx` 11 项（含换中心/返回/外部换选中清轨迹/剪枝提示）；`MermaidDiagram.test.tsx` 25 项（含标签索引、点击路由、Ctrl 深链、展开按钮）。
