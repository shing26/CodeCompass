# 票 06 — README 人话化 + Known Limitations

Status: closed（已落地，2026-10-19，tag v1.4.0）

## 背景
用户第四步：删掉假大空词汇、用人话描述痛点、明确列出已知限制。实测：无独立 Known Limitations 章节；边界散落各处；README 首句仍为口号（「让工具停止编造，让 Agent 停止猜测。」）；`CONTEXT.md:4` 版本滞后（写 1.2.0，实为 1.3.0）。

## 目标
一个资深工程师读 README 前 100 行后，能准确说出：这东西解决什么问题（人话）、怎么 30 秒看到效果、它做不到什么。

## 实现要点
1. **README 首段人话化**：采用用户原文句式——"大模型分析代码时经常把同名方法混在一起；我们用 TypeScript/Java 语法树在索引期把真实调用关系定死，每个结论带 file:line。"
2. **新增「## Known Limitations（已知限制）」**（README，紧接能力表）：
   - 只解析**静态显式**调用：运行时 `eval`、`apply` 动态绑定、反射/依赖注入容器组装、消息总线不在射程，链路在该处显式断开并标记（不是假装连着）
   - **TS/JS 模块别名（tsconfig `paths` / `baseUrl`）当前不参与模块路径解析**：跨文件关系按符号名绑定（先本文件、后最早声明），monorepo 同名符号可能错绑；别名不会报错——这是已知边界，修复已登记（票 08）
   - Go 隐式接口实现保持 dynamic（ADR-0018），不伪造 implements 边
   - Go/Java/TS 覆盖的语言清单与各自缺口（引用 v1.1 票 07 的既有表述）
   - 检索是关键词/子串匹配，不是语义检索（ADR-0002）
   - `install --ide` 早前装过的环境不会自动更新允许列表（重跑一次）
   - Node >= 24 硬约束；控制面无鉴权只监听本机
3. **CONTEXT.md 版本漂移修复**：`当前版本 1.2.0` → 实际值。
4. README 命令表补 `trace`（票 05）与示例项目入口（票 01）。
5. 边界措辞对齐既有 ADR（0002/0011/0018），不新增承诺。

## 验收
1. README 有 `## Known Limitations` 章节且六项限制逐条可对到 ADR 或实测证据（行内引用）。
2. README 前 100 行不再出现口号式绝对化句（人工核对 + 保留「零 LLM 依赖」这类事实陈述）。
3. `CONTEXT.md` 版本与 `services/control-plane/src/version.ts` 一致。
4. e2e 版本一致性棘轮不红（CONTEXT 不在棘轮内，但 README/HANDOFF 引用值须与 version.ts 一致）。
