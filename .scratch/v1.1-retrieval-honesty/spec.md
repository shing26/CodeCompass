## 0. 一句话

检索层（D4）是审计判定的最弱维度，但它的问题**不是"弱"，而是"从未被问过"**——实证：chunk 层全部量化证据只有 **1 条**样本，而 ADR-0002 设的翻案门槛正需要这类证据。本批的顺序写死：**先修一个真 bug → 再把缺口变成一条会红的门（豁免位 + 棘轮）→ 然后才允许扩覆盖 → 最后才谈索引升级**；同时把证据面里"存在但恒绿 / 已死 / 指针悬空"的东西清零。

## 6. 验收判据与纪律

1. **每票自带机器可验证判据**，写在票内 §验收；不接受"看起来对了"。
2. **棘轮纪律按指标方向区分**（票 12 已落地：`scripts/precision/ratchet-baseline.json` 带 `metric_direction`/`sampling` 字段，harness 与 `check_precision_ratchet` 按方向改写失败提示；票 06 **须**读同一 `sampling` 字段）：
   - **正向指标**（如检索 recallAtK）：只允许"收紧需理由"——提升阈值须 `--ratchet-update` + commit message 写明理由；
   - **反向指标**（孤儿比）：**放宽**才需理由（那可能是改进被看见），但必须附"假边条数"作为可读进度；
   - 任何阈值放宽都须在本 spec 追加记录。
3. **新增门必须证明会红**：门落地后须记录一次"故意破坏 → 门红 → 复原 → 绿"的可复现过程。
4. **chunk 计数变化同轮冻结**：票 03/04/05 改变 chunk 数后须同轮更新基线（票 04/05 内已列，一次冻结不抖动）。
5. **夹具扩样属"生产证据"**：为让缺口可测而补的夹具文件（票 02 的 TSX）不算范围外扩张。
6. **门禁全绿是合并前提**：控制面 **739** / web **347** / bridge 26 / e2e **71** 为 2026-09-28 实测对照（原 711/364 已过期，HANDOFF §2.1 已同步）；新增检查项须在票内更新 e2e 计数并同步 HANDOFF §2.1。
