### 1.1 纪律修订（双轨制，收口时改写 HANDOFF §2.2 的目标措辞）

- **MCP 面原封不动**：17 工具签名与数量冻结（v1 契约）；新增工具/改签名仍须附「降低误报或提升精度」论证。
- **Web 面换闸**：新增页签/大改的门槛由「精度论证」改为**「dogfooding 论证」**——提案必须回答「维护者日常使用频率与价值」；精度/检索类新面（体检、检索可视化）天然优先。
- **引擎侧纪律全部延续**：scan 定位红线（只报确定性事实，v0.21）、ADR-0018 桶语义、ADR-0002 真理之源、出库掩码不变式、copy-guard 双哨。
- **防漂移条款**：v031 定位文档诊断的「连续五个版本做界面不做产品」教训仍有效——dogfooding 论证闸就是防它复发的；「为界面而界面」的提案过不了闸。

## 5. 验收判据与纪律

1. **每票自带机器可验证验收**（票内 §验收）；不接受「看起来对了」。
2. **copy-guard 双哨全程执法**：新 UI 文案对照 `.scratch/v030-degeekify/spec.md` 四张权威表；**体检面文案守 v0.21 scan 定位红线 + ADR-0018**——孤儿桶只写「零静态调用者」（事实），禁写「可安全删除/死代码」（语义判断属 agent）。
3. **跨端契约改动先落票面**（票 03 的 SSE/WS 载荷）：contracts 镜像三处 + `contract-mirror` 哨同步，平行协作约定适用。
4. **UI 冒烟扩链路**：体检面、导入流化两条链路进 `scripts/smoke/ui_smoke.mjs`；e2e 计数同步 HANDOFF §2.1。
5. **收口仪式**（照 v0.31 惯例）：版本五处推进 v1.2.0 + CHANGELOG `[1.2.0]` 段 + 双轴 review（fixed point = 上次审完 commit）+ 全量门禁 + **Round4 全功能走查报告**（`docs/reports/`，截图 `ui-shots/`）+ 台账划销（V27-5/6/7/15/16、V29-1 关闭登记，冻结标注解除）。
6. **真用一周软验收**：发布后真实使用，反馈进增量 triage；不阻塞发版，但 P1 级反馈优先插队。

## 6. ADR-0020 底稿（收口时落 `docs/adr/0020-web-workbench-revival.md`）

> **ADR-0020: Web 工作台重新产品化（双面体再平衡）**
>
> **背景**：v0.31 方向裁决（定位文档 2026-09-16）将 Web 定为「演示厅与调试面、只减不增」，票 05（09-27）随之把一级导航收敛 6→3。冻结期内引擎侧精度资产持续积累（M1 重判、假边清零、棘轮门禁、FTS5 检索），工作台无面可承载；个人日常使用痛点（导入 600s 长挂、视图债冻结）持续无解。2026-09-28 用户访谈裁决反转。
>
> **决策**：Web 面重新产品化，目标 = 维护者本人日常使用的单机驾驶舱（dogfooding）。一级导航 chat/topo/gate/delta/体检五项；新页面/大改的门槛 = 「dogfooding 论证」（日常使用频率与价值）；MCP 17 工具冻结与「精度论证」门槛原样保留——**双轨制**。
>
> **理由**：双面体的 Web 端从「冻结」改回「投资」，把引擎精度兑现为日常价值；真实使用是本项目实证的最高效需求来源（BossHunter/codex 反馈全数消化，HANDOFF §2.4）。
>
> **否决的替代**：维持冻结（痛点持续积累、精度资产无日常出口）；团队/部署形态产品化（违 Local-First ADR-0001，V27-19 先例）；作品集演示门面定位（用户明确选择产品化而非演示包装）。
>
> **后果**：v0.31 spec §1.1 前两行放弃项失效（本 ADR 取代，原文不改写）；HANDOFF §2.2 纪律改写为双轨制；README/CONTEXT 定位词条随收口更新。Web 投入回升，但「dogfooding 论证」闸承担防漂移职责——v031 诊断的「连续五版做界面不做产品」教训仍然有效，为界面而界面的提案过不了闸。
