# CodeCompass 用户故事与扩展功能方案（v0.5.0 Polyglot）

> **⚠️ 已过时（superseded）**：本文基于 v0.5.0。E6（隐私呈现）已实现（§5 审阅点 1 失效）、E3 桥接已实现（审阅点 3 已在代码中回答：fetch/axios/apiClient 均支持）、D2 已闭环；E1/E2 亦已落地。当前有效的优先级、范围与 roadmap 见 [`.scratch/v0.6-closeout/spec.md`](.scratch/v0.6-closeout/spec.md)。本文的角色画像（R1–R5）与场景（S-A~S-E）仍然有效，可作为后续功能设计的用户参照。

> 阶段：**方案设计（待审阅）**。本文档仅输出方案，不含任何代码实现。
> 依据：CodeCompass v0.5.0 现状 + 端到端实测结论（`CodeCompass_E2E_验证计划.md` / `e2e-result.json`，复测 PASS=19 / FAIL=10）。
> 已知现状要点：Local-First、只读、确定性调用链（不调 LLM）、多语言适配器（Java/TS/JS/Python，Go 已实现未测）、8 个 MCP 工具、Graph RAG 子图、低置信度兜底、配置值永不落盘。
> 已知缺口（缺陷）：D1 大仓 50 万行上限误杀、D3/D4/D5 消费侧能力仅 Java 有效、D6 `/symbols` 的 `symbolType` 全为 unknown、D7 `.mjs` 未覆盖、D8 跨语言桥接未生效；D2（TS 调用链）本轮已闭环。

---

## 0. 方案目标

1. 从"功能清单"升级到"以人为中心"：明确**谁在用、用什么、为什么有价值**。
2. 把已发现的缺陷（D1–D8）转化为**可排期的扩展功能**，并补上高价值但当前缺失的能力。
3. 给出清晰的**范围边界、优先级与实施要点**，作为后续具体实现的验收基线。

## 1. 核心用户角色与典型场景

### 1.1 角色画像

| 角色 | 代号 | 核心目标 | 当前最依赖的能力 | 主要痛点 |
|---|---|---|---|---|
| 个人开发者 / 接手新仓者 | R1 | 快速理解陌生/自有代码 | 导入、dashboard、确定性调用链、低置信度兜底 | 大仓导入被拒（D1）、调用链仅底座层 |
| 新人工程师 / 入职者 | R2 | 低成本建立代码心智模型 | Tours、dashboard、reverse_deps、锚点跳转 | 缺可交互图、缺符号检索（D6）、缺跳转 |
| 技术负责人 / 架构师 | R3 | 守住改动风险与架构边界 | `get_pr_impact`、reverse_deps、跨语言视图 | 跨语言调用不可见（D8）、敏感路由无前端呈现 |
| AI Agent / LLM 应用开发者 | R4 | 让 Agent 基于本地代码事实回答 | 8 个 MCP 工具、`get_subgraph_context`、脱敏 | 跨语言桥接缺失、消费侧能力偏 Java（D3–D5） |
| 安全 / 合规审计员 | R5 | 证明敏感信息不落盘、可溯源 | 配置脱敏、masking/token 事件、Local-First | 脱敏/推理来源前端零呈现（AC-9） |

### 1.2 典型使用场景（叙事流）

- **S-A 接手陌生仓库**：R1 导入本地路径 → 看技术栈/路由/符号规模概览 → 输入一个入口方法名 → 得到确定性调用链图 → 点击节点跳转到 `file:line` 读源码。
- **S-B 新人 onboarding**：R2 打开仓库 → 自动生成上手导览（auth-chain / main-flow / error-handling）→ 用 reverse_deps 看"谁调用了关键函数" → 评估改动波及面。
- **S-C PR 合入前评审**：R3 选 base→head → 自动输出架构影响面（受影响 API、改动符号、配置键变化、未覆盖方法）→ 重点核对"无认证敏感路由是否被改"。
- **S-D Agent 代码问答**：R4 通过 MCP `list_repos` 发现仓库 → `trace_call_chain` / `get_subgraph_context` 取带脱敏与 token 裁剪的上下文 → 喂给本地/远程模型生成可溯源回答。
- **S-E 合规演示**：R5 导入含 `.env`/yaml 的仓库 → 验证 `configKeys` 仅暴露 `file:line`、导出 onboarding 不含值 → 查看 masking/token 审计痕迹。

## 2. 用户故事（覆盖主要流程）

> 格式：**作为\<角色\>，我希望\<需求\>，以便\<价值\>**。每条映射到当前能力或目标扩展（括号内）。

### R1 个人开发者
- US-1.1 作为个人开发者，我希望导入本地仓库后立刻看到技术栈、路由与符号规模概览，以便快速建立对陌生代码的心智模型。（dashboard；需 D3–D5 多语言化）
- US-1.2 作为个人开发者，我希望输入一个方法/路由名就能得到确定性调用链（mermaid 图），以便不读全部源码也理解某条请求的来龙去脉。（call-chain；D2 已闭环）
- US-1.3 作为个人开发者，当我问一个代码库里不存在的符号时，我希望系统明确提示"未定位到精确符号、以下为默认入口推导"，以便区分确定事实与推测、不被幻觉误导。（低置信度兜底；已可用）
- US-1.4 作为个人开发者，我希望超大仓库也能导入（不被行数上限误杀），以便对真实工作仓使用。（D1 修复；E1）
- US-1.5 作为个人开发者，我希望所有索引与查询都在本机完成、凭据永不落盘，以便在私有/商业代码上放心使用。（Local-First / 脱敏；已可用）

### R2 新人工程师
- US-2.1 作为新人，我希望打开仓库即看到自动上手导览（auth-chain / main-flow / error-handling），以便按图索骥熟悉核心链路。（Tours；已可用）
- US-2.2 作为新人，我希望查看"哪些方法调用了某关键函数"，以便评估改动某处的波及面、降低引入 bug 风险。（reverse_deps；已可用，缺 HTTP 端点 D8）
- US-2.3 作为新人，我希望调用链/子图里每个节点都能直接跳转到对应 `file:line`，以便边看边读源码。（锚点跳转；需 E4 可视化增强）
- US-2.4 作为新人，我希望能按符号名/类型搜索代码事实，以便从"全量列表"快速定位。（符号检索 UI；D6 / E7）

### R3 技术负责人 / 架构师
- US-3.1 作为技术负责人，我希望对一次 PR（base→head）自动分析架构影响面（受影响 API、改动符号、配置键变化、未覆盖方法），以便在合入前快速评估风险。（`get_pr_impact`；已可用）
- US-3.2 作为架构师，我希望 PR 影响分析能标记"无认证的敏感路由被改动"，以便守住安全红线。（pr-summary `--fail-on-auth-impact`；已可用）
- US-3.3 作为架构师，我希望多语言项目（Java 后端 + TS 前端）的调用关系能跨语言打通，以便端到端理解一个前端请求如何落到后端实现。（跨语言桥接；D8 / E3）

### R4 AI Agent 开发者
- US-4.1 作为 LLM 应用开发者，我希望通过标准 MCP 工具让 Agent 在本地读取代码事实，以便生成有代码依据、可溯源的回答。（8 个 MCP 工具；已可用）
- US-4.2 作为 Agent 开发者，我希望 subgraph 返回带 token 预算裁剪与凭据脱敏的内容，以便安全塞进上下文窗口且不泄露密钥。（`get_subgraph_context`；已可用）
- US-4.3 作为 Agent 开发者，我希望 `get_pr_impact` 只能分析已索引目录内的路径，以便防止 Agent 借机越权读取本机任意文件。（越权收敛；已可用，需 E3 补齐桥接）

### R5 安全 / 合规审计员
- US-5.1 作为安全审计员，我希望配置证据只暴露 key 的 `file:line` 位置、绝不暴露值，以便在审计/演示中证明敏感信息未落盘/未外传。（脱敏；已可用）
- US-5.2 作为合规人员，我希望能查看脱敏事件（masking.applied）与推理来源（本地确定性 vs 远程模型）的审计痕迹，以便满足合规留痕。（事件面；需 E6 前端呈现）

## 3. 扩展功能清单（目标 / 收益 / 关联现状）

| 编号 | 功能 | 目标 | 预期收益 | 关联现状 |
|---|---|---|---|---|
| **E1** | 大仓导入优化 | 仅计源码行；超限时提供子模块/目录选择器与可导入子路径建议 | 消除 D1 误杀，真实大仓可用 | D1（P0） |
| **E2** | 消费侧能力多语言化 | techStack / topApis / configKeys 支持 TS（`package.json`/路由装饰器）与 Python（`pyproject`/路由注册） | dashboard/tours/MCP 对全语言一致，兑现"多语言"承诺 | D3/D4/D5（P1） |

| **E4** | 代码透视可视化增强 | 调用链图可交互展开/折叠、点击节点跳 `file:line`、支持 caller/callee 双向视图切换 | 把"事实底座"变成可探索的图，可读性↑ | AC-2/AC-3 延伸 |
| **E5** | 增量索引与热重载 | FS watcher 增量刷新符号/调用边；大仓流式解析与并发优化 | 编辑即所见，提升大规模仓库伸缩性 | AC-12（P2） |

| **E8** | 自然语言问答接 LLM | 配置 `REPOQA_LLM_*` 后支持自然语言问答；确定性结果标 🟢、远程模型标 🟡，带 provenance | 从"确定性"扩展到"灵活推理"，复杂问题可答 | 架构延伸 |
| **E9** | 多仓库 / 工作区联合分析 | 跨仓库反向依赖、统一搜索、跨仓调用链 | monorepo/多服务一体化架构全景 | 架构延伸 |
| **E10** | 导入向导与子模块选择 UI | 可视化选择要索引的模块/目录（呼应 E1） | 导入可控，避免误杀/性能浪费 | E1 配套（P1） |
| **E11** | 测试 / 文档生成 | 基于 subgraph 自动生成单元测试骨架或接口文档草稿 | 把"理解"转化为"产出"，研发提效 | 架构延伸 |
| **E12** | 协作与分享 | 导出 onboarding tour / 子图快照为可分享文件，团队共用 | 知识沉淀，新人 onboarding 加速 | 架构延伸 |

## 4. 方案范围、优先级与实施要点

### 4.1 范围边界
- **范围内**：上述 E1–E12 的功能设计与后续实现（经确认后）；缺陷 D1–D8 的修复/闭环。
- **范围外（本期不做）**：真实 LLM 模型质量调优（仅做门禁与脱敏，不评模型效果）；多用户/团队权限（产品定位本地单用户）；Go 语言样本仓实测（适配器已实现，待提供样本）；移动端。

### 4.2 优先级（与缺陷优先级对齐）
- **P0（可用性 + 可信闭环硬门槛）**
  - E1（修 D1 大仓导入误杀）
  - E6（隐私药丸 + token/来源呈现，AC-9）——可信闭环的"可见化"是产品承诺的核心，建议提到 P0
  - 补 D2（TS 调用链）回归用例，防止回退
- **P1（多语言兑现 + 体验跃迁）**
  - E2（D3/D4/D5 消费侧多语言化）
  - E3（D8 跨语言桥接 + `/reverse-deps` HTTP）
  - E4（代码透视可视化）
  - E5（增量索引/性能）
  - E10（导入向导 UI，配合 E1）
- **P2（延展能力）**
  - E7（符号检索 UI / D6）、E8（LLM 问答）、E9（多仓）、E11（生成）、E12（协作）

### 4.3 实施要点（技术落点）
- **数据/适配器层**：在 `LanguageAdapter` 体系内补齐 consumer 能力（techStack/topApis/configKeys）的统一抽象；定义并落库 `symbolType` 枚举（修 D6）。
- **桥接层（E3）**：在扫描/调用解析阶段增加"HTTP 调用点 → 后端路由"的跨语言边，需识别 `apiClient` 等封装、解析 `baseURL` + path 模板；保守匹配 + 可解释，避免误桥。
- **前端（E4/E6/E7/E10）**：PrivacyPill + TokenCounter 组件；调用链图改用可交互渲染（mermaid 交互或自绘 SVG）；符号检索与类型过滤面板；导入向导。
- **增量与性能（E5）**：基于文件 mtime/哈希的增量解析 + 事件总线刷新证据面；大仓流式解析与并发；注意 SQLite 并发写锁策略。
- **测试回归**：复用 `codecompass_e2e_harness.sh` 作为基线，为 D2/跨语言/消费侧新增断言；修复后重跑直至 AC-1~AC-4、AC-8、AC-10 全绿。

### 4.4 风险
- 跨语言桥接依赖前端调用约定，易误匹配 → 需保守匹配 + 可解释、可关闭。
- 增量索引并发写 SQLite → 需事务/锁与幂等重导策略。
- LLM 问答（E8）接入需守住"确定性优先、远程仅补充"边界，防止幻觉回潮（与 v0.5.0 反幻觉定位冲突）。
