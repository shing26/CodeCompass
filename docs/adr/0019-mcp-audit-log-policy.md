# MCP 审计日志：记录入参出参，与 HTTP sink 的"排除 body"政策不同

评估维 E-M12（可观测与审计）此前是全表最低分（1 分）：`grep -c logger mcp/repoqa-mcp.ts` = 0，仓内 `log-sink.ts`（脱敏 / 4096 截断 / 5MB×5 轮转 / 14 天保留 / 写失败永不冒泡）**只接在 HTTP 侧**，17 个工具的调用没有任何入参 / 出参 / 耗时记录。补法是接线（票 12）：`registerPlain` 是全部工具的唯一出口，审计挂在那里，一处覆盖 17 个工具与未来所有工具；`McpDeps` 增**可选** logger（单测不注入 ⇒ 不写文件、保持 hermetic），`runMcpServer` 从 dataDir 构造 sink 注入。

**三处需要留痕的判断**：① **记录入参出参**——评分分档的 2 分要件逐字要求「每次调用有日志（入参/出参/耗时/结果）」，而 HTTP sink 的政策相反：它明确「请求头/请求体永不入内（query 亦排除，R5 review P2-1）」。本 ADR 判定两者**不矛盾而是面不同**：HTTP 面记录的是**用户**对本地服务的请求（隐私优先），MCP 面记录的是**宿主 agent 自己**的工具调用，其入参是 agent 的意图（repoId / 符号名 / query），审计价值高于隐私成本。② **落盘形态**：args/result 以 JSON 字符串入库并复用 sink 的 `sanitize`（`maskSensitiveText` 深走 + 每串 4096 截断），因此单行有上界、凭据必被掩码；**不入自建序列化**——掩码不变式（R1）由此延伸到 MCP 面。③ **复用同一份 `control-plane-<date>.jsonl`** 而非新开文件：轮转/保留/降级策略一套，靠 `scope:'mcp'` 区分（`SessionLogger` 独立文件是因为会话取证语义不同，MCP 调用审计不构成第二语义）。

**被否决的备选**：为新语义单开 `mcp-audit-*.jsonl`（多一套轮转与保留要解释，收益只是文件更干净）；只记 `argsBytes` 不记内容（省空间但**不满足 2 分要件**，等于没做）；异步批量落盘（当前同步 append 已由 sink 保证不冒泡，先按最简单形态落地，出现可见变慢再优化——票 12 风险节已登记该触发条件）。

**后果**：新增已知边界——**经 SDK 输入校验拒绝的调用不进入 handler，因此不在审计内**（校验发生在包装函数之前）。这不是缺陷而是分层的必然，已写入票面与统计脚本头注释，避免日后把「成功率」误读成「含被拒调用」的总口径。新工具的审计**自动生效**（接线在收口点，不在各工具内）；日志字段一旦落盘即成事实面，改动需按本 ADR 复核。
