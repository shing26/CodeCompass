# Pattern Ingestion：惯例断言证据化，近邻优先仲裁

grilling 裁决（Issue 24 酝酿会话）。演进建议生成前对目标代码库做确定性模式嗅探，产出按作者划三层：**惯例清单**（引擎，新复合工具：统一返回包装、接口-实现风格、Base 类、DI 风格、包路径惯例等轴；每条断言带物理锚点 + 覆盖率，如「Controller 统一返回 `ApiResult<T>`：12/12，样本 `OrderController.java:15`」）；**落位表**（引擎，EXTEND 管线扩展：规范包路径、注入点 file:line、事务边界）；**骨架代码**（LLM，消费惯例清单作上下文，按 ADR-0006 标注 `llm-generated`、人工审核、永不落盘）。契合度因此机器可验收：落位表与惯例清单的一致性由引擎自查。

仲裁规则：惯例分裂时**近邻优先**——落位目标同包/同业务域兄弟模块的惯例先于全局统计；近邻自身分裂或无近邻时退**全局多数决**；任何裁决**强制披露**（异类清单 + 锚点进工件卡），不输出双变体（Intent→Artifact 禁反问，ADR-0012）。

理由：惯例断言（"现有模块返回统一包装类"）是对代码库的事实主张，必须纳入零幻觉合约（ADR-0011），锚点 + 覆盖率是其验收形态；"同类模块"是规则②原话，近邻即其操作化——新代码 join 的是落位目标的近邻队伍，不是全仓平均；多数决兜底保证单次产出完整（Intent→Artifact）。否决方案：全局多数决单轨（跨业务域的惯例差异会让 7/12 的全局统计误导落位）；双变体输出（把裁决责任推回用户，稀释信息完成度，且骨架倍增）。代价：新引擎管线（嗅探轴逐轴实现）；eval 需新增惯例锚定正确率 bucket。工具命名与嗅探轴 v1 清单留 Issue 24 spec。实施随 Issue 24。
