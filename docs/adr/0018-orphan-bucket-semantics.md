# 孤儿桶语义收窄：桶只声称「可调用符号的零静态调用者」

v0.31 精度攻坚的实测把孤儿桶推到了一个必须裁决的位置：lazygit 全桶 2805 条里，**1618 条（58%）不是引擎不够好，而是桶声称了一件静态分析做不到的事**——类型声明 623（类型没有"调用者"这个概念）、接口方法声明 375（契约成员）、接口实现方法 620（Go 接口多实现时 ADR-0002 要求保持 dynamic，而"零静态调用者"不等于死代码）。结论：**收窄桶语义，而不是补边**。理由是桶的**定义**错了，不是引擎弱了——top-10 假阳性 100% 且 receiver 绑定类工作已被实测证明推不动它（报告 §7.1：精度工程已把"可修的都是可修的"）。补类型引用边（追踪 import / 字段类型 / 泛型实参）被否决：三仓三套适配器都要动，成本高一个数量级，而报告已证明它不推动 M1。三项裁决逐条落地：

1. **类型声明不进候选**（批准 A）：孤儿候选收窄为 `kind === 'method'`。桶从此声称"可调用符号中的零静态调用者"，`class`/`interface`/`service`/`repository`/`config`/`advice`/`mapper`/`sql` 一律不进候选，且**按规则计数回报**（`excludedByRule`），不静默消失——"某个类型从未被任何地方引用"是另一类结构事实，需要别的出口，不属于本桶。
2. **接口成员不进候选**（批准 A 为目标态、A′ 为执行路径）：A′ 第一步先做**接口方法声明**（可判：method 且其 owner 是 interface 声明）——便宜、确定性、无需新表；**接口实现方法**（620，占剩余噪声三分之一）留待接口-实现关系表建成后再收，本次以 `deferred` 规则显式登记在响应里。不采用"只收声明、实现留桶当可疑"的中间态：报告已实证代表样本（`Instruction.Kind` 一族）**确实**在 `ToEnvVars` 里被调用，只是走接口分派——把它们当可疑，等于把 35% 的结构性噪声永久留在桶里。
3. **测试调用不计入调用者，但标注 `testOnly`**（批准 B）：本项是三项里唯一"桶说得对"的——只被测试调用的生产代码本身就是可疑信号，因此**不排除**、也不改口径让测试调用算作调用者（那是纯数字游戏），只加确定性标注，让 agent 知道这个符号的 in-degree 为 0 是因为生产调用图里确实没有它。不采用"排除"：那会掩盖真信号，而它仅占 3%，对 M1 影响最小。

**必要条件（三条，缺一即违背本次裁决）**：① ADR 与工具描述、README 同步写明桶的**声称范围**已收窄为可调用符号，否则口头仍声称覆盖类型，是新的文档漂移；② 被排除的类必须是**可复算的计数**（`excludedByRule` + `testOnly` 计数必须与 `total` 守恒），不接受"数字变小了但说不清少了什么"；③ 报告纪律继续生效——**不允许按目标倒推口径**：收窄的判据是"桶的声称是否成立"，不是"能否把 M1 压到 5%"。附带一条前置：全桶归因原先是临时诊断产物（`runScan` 只发布前 10 条候选），本次把归因做成响应内的确定性普查，使裁决结果可复跑。

**后果**：lazygit 孤儿 2805 → **1807**（−623 −375）；接口实现项落地后为 **1187**，此时 M1（top-10 假阳性率）才**有资格**变动——注意这只让它有资格，不保证它达标：剩余最大的一块是"零调用者且全量索引里也无调用者"的 1093 条，报告尚未逐条核验。剩余副产物：`scan` 的桶语义与 M1 的口径必须一起读，否则会重演 v0.21「水位」与「率」混用（报告 §6 已记该歧义来源）。
