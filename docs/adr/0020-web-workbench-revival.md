# Web 工作台重新产品化：双面体的再平衡（v1.2）

v0.31 方向裁决（2026-09-16 定位文档）把 Web 定为「演示厅与调试面、只减不增」，票 05（09-27）随之把一级导航收敛 6→3、README 首句改为「代码事实层，主轴 MCP」，HANDOFF 并写明「Web 界面长期搁置，文档不得再把它写成产品面」。冻结期内引擎侧精度资产却在持续积累：M1 重判与 top-10 整榜换血、1014 条假边归零、扫描棘轮与真仓账实门、FTS5 检索与 chunk 覆盖 73→3389——**这些能力在 Web 面上没有任何入口**；与此同时个人日常使用痛点（导入最长 600s 同步长挂、视图债冻结、拓扑降为深链）持续无解。2026-09-28 用户访谈（`.scratch/v1.2-workbench-revival/spec.md` §1 D1–D8）裁决反转：**Web 工作台以「维护者本人每天真用的单机驾驶舱」为目标重新产品化**。本决定不改变 ADR-0001（只读、本地优先）与 ADR-0012 双面体的架构：MCP 仍是主轴，17 工具签名与数量继续冻结；变的是 Web 端从「冻结」改回「投资」。

**决策**：一级导航定为五项 chat / 代码拓扑 / 变更审计 / Diff 影响面 / 体检（scan）；metrics 并入 more 菜单一跳可达，evolve 留深链。**双轨制纪律**取代 v031 的单闸：MCP 面维持「新增工具/签名变更须附精度论证」；Web 面新增页签/大改的门槛改为「dogfooding 论证」——必须回答维护者日常使用频率与价值，精度/检索类新面天然优先。引擎侧纪律全部延续（scan 定位红线「只报确定性事实」、ADR-0018 桶语义、出库掩码不变式、copy-guard 双哨）。防漂移条款：v031 定位文档诊断的「连续五个版本做界面不做产品」教训仍然有效，「为界面而界面」的提案过不了 dogfooding 闸。

**被否决的备选**：维持冻结（痛点持续积累、精度资产无日常出口——v1.2 六张票本身就是反证）；作品集演示门面定位（用户明确选择产品化而非演示包装）；团队/部署形态（违 Local-First，v0.29 T7 企业套件三不做先例：重评触发线=多租户/托管形态出现）；把 Web 升为「产品面而 MCP 降级」（README「主轴 MCP」的口径在 v1.2 收口时仅补充 Web 产品面地位、不翻转主次）。

**后果**：v0.31 spec §1.1 前两行放弃项失效（本 ADR 取代，原文留档不改写）；HANDOFF §2.2 纪律改写为双轨制；README/CONTEXT 定位词条随 v1.2.0 收口更新。Web 投入回升带来的具体承诺以 v1.2 spec §5.1 完成定义为准：波 1+2 全落（IA 还原、体检面数据面、导入 202+WS 流化、视图小债包、a11y）、票 06 检索分区落地（真用一周零使用则按 Web 闸撤下——登记在票面）、收口出 Round4 体验报告；发布后真用一周为软验收，反馈进增量 triage。已知代价：导入转 202 是破坏性 REST 变更（CHANGELOG [1.2.0] 破坏性段在案）；体检面/检索面新增的是**读面**，引擎零改动——「同引擎同输出」由 cp 测试的 deep-equal 断言把守。
